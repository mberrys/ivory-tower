## Environmental blocker (NOT a Session 00 change, NOT a repository code defect)

  10. typecheck:ivory-tower         FAIL  - @ivory-tower/domain:compile
      error TS5033: Could not write file
      'C:/.dev/repos/ivory-tower/packages/ivory-tower-domain/lib/execution.d.ts.map':
      EPERM: operation not permitted

  Root cause: lerna (v9 / nx) run from a LINKED GIT WORKTREE resolves every package location to
  the PRIMARY checkout, not to this worktree:

    $ npx lerna list --all --json
      "@theia/application-manager"  "location": "C:\\.dev\\repos\\ivory-tower\\dev-packages\\application-manager"
      (i.e. C:\.dev\repos\ivory-tower\..., NOT ...\.claude\worktrees\new-session-1dda69\...)

  So `lerna run compile` tries to write build output into the PRIMARY worktree. Under the Codex
  sandbox, a write outside this session's worktree is denied -> EPERM on the first .d.ts.map.
  `nx reset` does not change the resolution; it is lerna's repo-root detection under git worktrees.

  The package itself compiles cleanly IN THIS WORKTREE:

    $ cd packages/ivory-tower-domain && npx tsc --project .        -> exit 0 (writes lib/execution.d.ts.map, 1482 bytes)
    $ cd packages/ivory-tower-domain && npm run compile            -> exit 0 (ts-clean-dangling && tsc)

  Session 00 modified zero TypeScript and zero package source. The same class of pre-existing,
  environment-bound failure was recorded (not chased) by Session 03 for the Windows build:electron
  step.
